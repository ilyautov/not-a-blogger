# AGENTS.md: not-a-blogger

Instructions for an AI agent (Claude Code, Codex, Cursor) working in this repo: helping a person build a video from
recipes, or preparing a contribution. `CLAUDE.md` includes this file.

## The contract

This kit is a toolkit, not a content strategy. The person decides what to make; you make it well and measurably.

1. **Script first.** Show the lines before building anything; wait for the person's answer.
2. **Build, then measure.** Finish every build with QA on the final file (frame fill, dead frames, ASR of the voice,
   loudness) and a contact sheet. Report the file path, its SHA256 and what was *not* checked. The pass values and
   where each one came from are in one table: `docs/QA-THRESHOLDS.md`; don't invent a stricter or looser number in a recipe.
3. **A green QA is not approval.** `artistic_approval` and `publication_approved` stay `false` until the person flips
   them. Never publish, upload or post anything yourself.
4. **Their language, their niche.** The author used this kit for Russian shorts about AI tools; nothing in the recipes
   requires that. Recipes with `lang: ru` are language-specific: tell the person the equivalent for their language is
   missing instead of applying the Russian one silently.
5. **No numbers, no "proven".** When you write a recipe or a gotcha, measurements go into Evidence; without them the
   status is `hypothesis`.

## Map

- `recipes/<section>/<id>.md`: agent recipes (When / Do / Verify / Don't / Evidence). Index: `recipes/README.md`; by symptom: `recipes/BY-SYMPTOM.md`;
  machine-readable: `recipes/index.json`; `docs/CHANGELOG.md`. All four are generated by `scripts/build_index.py`.
- `learn/<lang>/`: textbook for humans. Read a chapter when you need the "why" behind a recipe (`learn:` field).
- `tools/`: CLI utilities, see `tools/README.md`; tests in `tests/`.
- `templates/`: project skeletons (3D skit, data reel, experiment, dialogue skit, real-tool reel).
- `starter/`: reference build (`make.sh`), voice, ASR and QA report. ASR language: `ASR_LANG` (default `ru`).
- `starter-lite/`: 15-second Node-only HyperFrames project, no Python or voice; a first render for newcomers. Use it only
  when the person has no Python (see "Which build to use").
- `examples/`: breakdowns of published videos.
- `gotchas/README.md` and `gotchas/lang/<code>.md`: pitfalls with numbers.
- `prompts/`: prompts for script, hook, fact check, frame review, image and video generation.
- `research/`: anonymized findings.

## Which build to use

Ask the person what they have, then pick one; say which and why in one line.

| The person has | Build in | What they get |
|---|---|---|
| Node and ffmpeg only, no Python, wants to see the engine | `starter-lite/` | a 15-second mp4 from three HTML scenes; no voice and no QA, so tell them the checks live in `starter/` |
| Python 3.11 + Node, wants a finished video with voice and a QA report | `starter/` (default) | lines in, `output/final.mp4` + `qa/final-result.json` + `qa/sheet.jpg` out |
| A specific format: a two-character skit, a reel on measured numbers, a test of someone's advice, a real tool on camera | `templates/<name>/` (`3d-skit`, `skit`, `data-reel`, `experiment`, `real-tool-reel`) | the skeleton for that format; read its README first |

Not sure: `starter/`. Never build inside `examples/` or `recipes/`.

## Route: first video, ten stages

Each stage has a "done when" check in `learn/en/00-first-video.md` (Russian: `learn/ru/00-first-video.md`). Don't
move to the next stage until the current one is done, and show the person the result of stages 2, 6 and 8.

| # | Stage | Done when (short) | Recipes |
|---|---|---|---|
| 1 | Idea | fits "who, what happened, how it ended"; a reference link next to it | `recipes/idea/` |
| 2 | Hook and script | 5–10 lines for 30–60 s (the starter demo has 3); the first line says what happened; **the person approved them** | `recipes/hooks/`, `prompts/` |
| 3 | Humanizer pass | scanner quiet, numbers and names match the source | `recipes/text/` |
| 4 | Voice | one file per line, recognized text matches, no eaten first or last word | `recipes/voice/`, `gotchas/lang/<code>.md` |
| 5 | Picture | for every line it's clear what's in frame; every third-party image has source and license | `recipes/image/`, `recipes/camera/` |
| 6 | Assembly | `./make.sh all` exits 0, `output/final.mp4` exists, `still_lint.py` finds no dead scenes | `recipes/assembly/` |
| 7 | Sound | QA passes loudness and peak; the voice is audible over music | `recipes/sound/` |
| 8 | Checking | contact sheet built and looked at; QA report shown to the person with what was *not* checked | `recipes/qa/`, `docs/QA-THRESHOLDS.md` |
| 9 | Vertical | text in the vertical no smaller than the original, nothing off the edge | `recipes/vertical/` |
| 10 | Publishing | **only the person publishes**; you prepare title, description and checklist | `recipes/publishing/` |

## When a person builds a video

1. Find recipes first: `grep -ril "<keyword>" recipes/`. Don't invent a technique when a recipe exists.
2. Before voice synthesis read `recipes/voice/` and `gotchas/lang/<video language>.md`.
3. Show the person the script before building: every line (5–10 for a 30–60 s video, as in stage 2 above) and one
   storyboard. Building without an agreed script usually produces slop.
4. Green automated checks do not mean the video is done. Build a contact sheet (`recipes/qa/`) and look at it before
   saying "done".
5. Never publish or upload anywhere. Only the person publishes; you prepare title, description and checklist.
6. Write viewer-facing text in the video's language; prompts take a `{language}` placeholder.

## When you prepare a contribution

- Recipes follow `templates/recipe.md` strictly, in English. File name equals `id`.
- Only numbers the person measured or that appear in a source go into Evidence. No numbers: `status: hypothesis`.
- Not tested on a real video means `hypothesis`, however convincing it reads.
- Language-specific recipes set `lang:` and invite a sibling in other languages.
- Don't copy code from AGPL, GPL or unlicensed repos.
- Before a PR run `python3 scripts/lint_recipes.py`, `python3 scripts/build_index.py` and
  `bash scripts/privacy_check.sh`.

## Don't

- Don't commit mp4, model weights, voice references or music. Link them.
- Don't use the author's mascot, logo or palette in your recipes (see `docs/BRAND.md`).
- Don't advertise other products. A tool is mentioned only when the recipe doesn't work without it, with its license
  and limits.
