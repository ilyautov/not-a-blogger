# Plan the shots

In the not-a-blogger checkout, read [AGENTS.md](../../../AGENTS.md). Input: approved lines, intended audience,
format and existing visual constraints. Keep the text; flag a line that cannot be staged rather than rewriting it silently.

Use the [direction map](../../../starter/.agents/skills/reels-direction/SKILL.md) to choose a suitable delivery:
observable action, evidence reveal, comparison, explanation or sketch. Tie each shot to what the viewer learns.
For a physical gag, preserve cause and effect between object states. A list or tutorial need not become a gag.

Record visible object/character, action, framing, needed assets and the state before/after each beat in the existing
[brief](../../../starter/BRIEF.md) or a storyboard. Define the first frame and payoff frame. Check caption space and
phone readability early. The [style atlas](../../../learn/en/04-image-and-frame.md) helps choose a treatment;
its static studies do not establish animation quality.

Output: a shot plan and asset requirements that can be handed to the assets/motion stages, with unresolved material
explicit. A storyboard is a plan, not a rendered frame. Do not synthesize speech, generate artwork or build scenes here.
