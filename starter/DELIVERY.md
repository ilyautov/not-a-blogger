# Что отдать после сборки

Вход: точный `output/final.mp4`, свежий `qa/final-result.json`, бриф и выбранные медиа.
Не отправляйте весь рабочий каталог: там могут быть голосовой референс, записи, кэш и приватные checkpoint.
Перед внешней передачей владелец выбирает конкретные файлы. Публикация требует отдельной команды.

## Пакет результата

| Файл | Содержание | Проверка |
|---|---|---|
| `output/final.mp4` | Точная версия ролика | Открыть, посмотреть и прослушать целиком |
| `qa/final-result.json` | Машинный QA этого MP4 | Сверить SHA256, статусы, checks и непропущенный ASR |
| `qa/sheet.jpg` | Контактный лист | Состояния, обрезка, крупности; непрерывное движение не подтверждает |
| `BRIEF.md` | Реплики, события, R-ID, URL, решения | Финал выполняет обещание начала |
| `PASSPORT.md` | Заполненный паспорт ниже | Каждое утверждение имеет результат или «не проверено» |
| `MEDIA-SOURCES.md` | Происхождение и права каждого файла | Источник, автор, условия, изменения, дата |
| `CAPTION.md` | Черновик подписи | Суммы/факты/ссылки и уместный следующий шаг |

Команды для независимого сопоставления:

```sh
shasum -a 256 output/final.mp4
ffprobe -v error -show_entries format=duration,size -show_entries stream=codec_name,width,height,r_frame_rate -of json output/final.mp4
cat qa/final-result.json
```

Если SHA256 паспорта и QA расходятся, остановите выдачу и выполните `./make.sh finish` для текущей полной картинки.
Для fake-версии не стирайте `preview_partial` и причину пропуска ASR.

## Паспорт: поля для заполнения

```text
Название и версия:
Дата сборки:
Файл и SHA256:
Длительность / размер / разрешение / fps / кодеки:
Голос: своя запись или TTS; модель/версия, если применимо:
Технический статус и обязательные checks:
ASR: модель, нормализация, совпадение/расхождения, пропуски:
Финальный AAC: LUFS / dBTP:
Изученные кадры и обнаруженные проблемы:
Непрерывное движение просмотрено: кем, когда, точный файл / не проверено:
Звук прослушан: кем, когда; ударения, окончания, музыка / не проверено:
На телефоне проверено: каким человеком / не проверено:
Художественное принятие: точные слова владельца и дата / не получено:
Разрешение публикации: площадки и точная версия / не получено:
Оставшиеся ограничения:
```

`ready_for_user_preview` означает техническую готовность. Даже точный ASR не оценивает ударения,
интонацию, комедийную отдачу и художественное качество. Не заполняйте эти поля автоматически как успешные.

## Источники медиа

Для каждого фото, видео, музыкального трека, шрифта и графического элемента укажите:
имя файла → автор/владелец → исходный URL либо собственная запись → дата получения → лицензия/разрешение →
сделанные изменения → нужная подпись. Для генерации: инструмент, модель, дата, промпт и использованные референсы.
Файл из интернета не становится свободным от прав после обрезки. Встроенный пэд создаёт tools/sound.py;
шрифты сопровождаются скачанными OFL. Стемы лежат до финального мастеринга и по громкости отличаются от AAC в MP4.
Личные WAV/TXT референса в публичную выдачу не включайте.

## Черновик подписи

Сначала конкретный результат или ситуация из ролика. Затем условие/граница, если без неё меняется смысл.
Для учебной подписки: «Учебная сцена: 200 ₽ уже списано, продление отключено, следующий платёж 0 ₽.
Это пример ролика из кода; возврат денег здесь не показан и не обещан».
После отдачи — уместный следующий шаг. Заполните свои проверенные ссылки и атрибуцию музыки/медиа.
В подпись добавьте ссылку на ваш канал и ваш сайт (плейсхолдер: «ваш канал»);
нарезка лонга также ссылается на исходный полный ролик.

Выход: готовые файлы и проверяемый отчёт, публикационных действий ещё нет.
Типичный отказ: подпись обещает охват или результат продукта, который в ролике лишь нарисован. Сузьте её до показанного опыта.
