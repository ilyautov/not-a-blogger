## Что можно принести за вечер

| Вклад | Куда | Объём | Форма issue |
|---|---|---|---|
| Грабли TTS на своём языке | `gotchas/lang/<код>.md`, одна строка | 15 минут | «Грабли» |
| Общие грабли (ASR, рендер, площадка) | `gotchas/README.md`, одна строка | 15 минут | «Грабли» |
| Новый рецепт для агента | `recipes/<раздел>/<id>.md` по [шаблону](../templates/recipe.md), на английском | 1 час | «Приём» |
| Языковой рецепт-двойник | рядом с рецептом `lang: ru`, тот же раздел, `lang: <код>` | 1 час | «Приём» |
| Разбор своего ролика | `examples/<slug>/README.md` | 1 час | «Мой ролик» |
| Ролик, сделанный набором | строка в [MADE-WITH.md](MADE-WITH.md) | 5 минут | без issue, сразу PR |
| Перевод главы учебника | `learn/<код>/` по образцу `learn/en/` | вечер | «Перевод» |
| Поправка цифры или устаревшего рецепта | правка файла + `updated:` в шапке | 15 минут | «Рецепт устарел» |
| Утилита | `tools/<группа>/<имя>.py` + тест в `tests/` | вечер | «Приём», с пометкой «инструмент» |
| Шаблон проекта | `templates/<имя>/` с README | вечер | «Приём», с пометкой «шаблон» |

## Рецепт и учебник

- **Рецепты** (`recipes/`) пишутся для агента: коротко, повелительно, с параметрами и проверкой. Только английский.
- **Учебник** (`learn/`) пишется для человека: почему так, живые примеры, ошибки. У каждого языка своя папка.

Новый приём обычно начинается с рецепта. Если его нужно объяснять, добавь подраздел в главу `learn/ru/` и, если
получится, в `learn/en/`.

Не знаешь, с чего начать? Открой issue с меткой `good first issue`: у каждого такого есть путь проверки и человек,
который ответит. Как раздаются метки, описано в [TRIAGE.md](TRIAGE.md).

## Правила для рецепта

1. **Один приём, один файл.** Если приёма два, делай два файла и связывай их через «Связанное».
2. **Проверь, что такого ещё нет.** Поищи по `recipes/`. Если есть похожий, дополни его, а не дублируй. В issue
   напиши, чем твой приём отличается от существующего.
3. **Цифра или честная гипотеза.** `status: proven` ставится только при замере, A/B или метрике опубликованного
   ролика. Без цифр пиши `status: hypothesis`, такой рецепт тоже примем. Это проверяет `scripts/lint_recipes.py`:
   `proven` проходит только с `evidence: measurement`, `ab-test` или `video-metric`; `experience` и
   `viewer-feedback` идут с `hypothesis`. Пороги проверок живут в `docs/QA-THRESHOLDS.md`, а не в рецептах.
4. **Воспроизводимость.** Команда или код в разделе «Приём» запускаются без платных ключей API. Если приём требует
   платной модели, так и напиши в разделе «Don't».
5. **Чужое с лицензией.** Код, музыку, шрифт или картинку из чужого проекта указывай со ссылкой и лицензией. Код под
   AGPL и GPL, а также репозитории без лицензии сюда не копируем, можно только описать идею своими словами.
6. **Без личного.** Никаких путей вида `/Users/имя`, ключей, токенов, референсов чужого голоса и лиц без согласия.
   CI это проверяет: `scripts/privacy_check.sh`.
7. **Языковые рецепты** ставят `lang:` и зовут принести двойника на другом языке. Линтер это проверяет: в рецепте
   с `lang:` не равным `any` должно быть слово «contribute», готовая строка есть в конце
   [шаблона](../templates/recipe.md). `lang` это язык речи или текста, от которого зависит приём (грабли TTS, привычки
   ASR, сканер нейротекста), код ISO 639-1; `any`, если приём от языка не зависит. Двойник кладётся отдельным файлом
   в тот же раздел со своим `lang:` и своими цифрами, оба файла ссылаются друг на друга в «Related»; если приём тот
   же и отличается только язык, предлагаем давать id суффикс кода языка (`voice-f5-sacrificial-first-word-de`);
   двойников в наборе пока нет, это предложение, а не сложившееся правило.
8. **Текст человеческий.** Русские тексты (учебник, разборы) желательно прогнать через
   [humanizer-ru](https://github.com/ilyautov/humanizer-ru). Это не обязательно, но ревьюер всё равно попросит убрать
   «стоит отметить» и «является ключевым».
9. **Два слова для двух людей.** В инструкциях рецепта *the person* — тот, кому помогает агент: он одобряет сценарий,
   слушает голос, публикует. В доказательствах *the author* — тот, кто снял замеренные ролики. «The user» и «the owner»
   не используем.

## Правила для разбора ролика

- Метрики бери из аналитики площадки, с датой снятия. Не округляй вверх.
- Провалы приветствуются. Разбор «почему 3 просмотра» полезнее десятого «как я набрал миллион».
- Медиа по ссылке, mp4 в git не кладём. Постер-кадр до 100 КБ можно.
- В кадре нет лиц людей, которые не давали согласия.

## Проверки перед PR

```bash
python3.11 -m pip install -r requirements.txt pytest
python3.11 -m pytest tests/       # тесты утилит (CI гоняет Python 3.11)
python3 scripts/lint_recipes.py   # рецепты, ссылки учебника, совпадение глав ru/en
python3 scripts/build_index.py    # пересобирает recipes/README.md, recipes/index.json, recipes/BY-SYMPTOM.md, docs/CHANGELOG.md
bash scripts/privacy_check.sh     # личные пути, ключи, референсы голоса
```

CI гоняет то же самое на каждый PR.

## Работа с агентом

Пишешь рецепт вместе с Claude Code или Codex? Дай агенту [AGENTS.md](../AGENTS.md): там правила оформления и проверки.
Рецепт, полностью написанный агентом без твоей проверки на реальном ролике, ставь со статусом `hypothesis`.

Спорим о приёмах и цифрах, не о людях. Ревьюер может попросить замер, это не недоверие, а правило набора.
Полные правила и куда писать о нарушениях: [CODE_OF_CONDUCT.md](../CODE_OF_CONDUCT.md).
